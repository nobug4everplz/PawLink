## 怎麼重跑

```bash
SUPABASE_URL=https://<專案>.supabase.co SUPABASE_ANON_KEY=<publishable key> QA_PASSWORD=<測試帳號密碼> npm run test:acceptance
```

- 需先在 Supabase 的 Authentication 設定關閉 Confirm email。
- 會建立三個測試帳號 `pawlink-qa-owner`、`pawlink-qa-user`、`pawlink-qa-care`（網域預設 `example.com`）。
- 測試資料放在外海座標（25.300, 122.200），結束時刪除動物與餵食紀錄並把測試點停用，不會出現在地圖上。

## 管理員測試

管理員角色無法從前端自行取得（這是設計）。第一位管理員要在 Supabase 的 SQL Editor 設定一次：

```sql
update public.profiles set role = 'admin'
where id in (select id from auth.users where email in ('pawlink-qa-admin@example.com'));
```

想讓自己的帳號也是管理員，把自己的 Email 加進清單即可。設定後重跑驗收腳本，會多出 4 項管理員測試。

## 實測中修掉的問題

- 動物身分檔點步驟更新結紮進度會失敗（前端多送了沒有寫入權的 `tnr_updated_at` 欄位）。已改為只送 `tnr_stage`，時間由資料庫自動更新。
- 結紮進度原本要點很小的步驟文字，沒有權限時也沒有任何反應。已改成一列一個階段、點了先確認，沒權限會說明原因。
- Vant 元件的按鈕文字是簡體中文，已改為繁體。
- 餵食點面板無法關閉。已加上關閉鈕，點地圖空白處也會收起。
- 清理提醒原本只在點開該餵食點時才看得到。現在地圖頁上方會顯示「你有 N 筆餵食還沒回報清理」，點了直接跳到該點。

## 已知限制（留待後續階段）

- 剛餵完、還沒到清理時間的紀錄也會算進清理率的分母，所以剛餵完會暫時顯示較低的清理率。
- 最後一位 owner 退出後該點沒有 owner，需由管理員指派（階段 2 管理員後台）。
- PWA 加入主畫面與離線補傳屬階段 4；資料庫端的防重複補傳已備好並通過測試。
- Demo 前請在 Supabase 清掉測試帳號與停用的測試點。

## 已知限制

- Turnstile 是選配，還沒有用真的金鑰驗證過成功路徑，見 `docs/turnstile-setup.md`。
- 頻率限制以來源 IP 為準，同一個 Wi-Fi 或行動網路出口的人會共用額度。
- 驗收腳本從雲端主機執行時會經過兩個出口 IP，所以前兩次通報各算各的、第 3 次才被擋。一般手機或家用網路只有一個出口，第 2 次就會被擋；這一點還需要用手機實際連送兩次確認。
- 站內通知是地圖頁的數字與收件匣，每 5 分鐘更新一次，沒有推播。
- 介面流程是接本機資料庫驗證的，正式站要等 migration 套用後再實際走一次。

## 已知限制

- 正式環境的 pg_cron 排程還沒實際看過它跑。套用 migration 後，後台「哨兵」分頁會顯示排程有沒有啟用與上次自動檢查時間；沒有啟用時仍可手動執行。

- 提醒只在站內顯示（地圖頁「通知」的數字），沒有推播。
- 平均出現間隔很長的動物（例如一個月才被回報一次）門檻也會跟著變長，這是決策表的公式本來的結果。

- 接力看板列出全站進行中的案件，沒有依距離或餵食點篩選。
- 輪到自己的任務只在站內顯示（地圖頁「接力」的數字），沒有推播。
